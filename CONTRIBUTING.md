# Contributing

This is a living guide. Corrections and additions are welcome, especially from people who just went through it and hit a rough spot. If a step confused you, that's a bug worth reporting.

## Good contributions

- **Fixes for outdated info** — a pricing change, a renamed menu, a screenshot that no longer matches the UI.
- **Broken or dead links** — every external link should be real and reachable.
- **Clearer explanations** — if a section tripped you up, a plain-language rewrite helps the next person.
- **New beginner-friendly examples** — an automation workflow, a small MCP server, a CLAUDE.md pattern that worked well for you.

## House style

Keep the tone this repo already uses:

- **Beginner-first.** Assume the reader is smart but new. Define jargon or link to the [glossary](./01-foundations/glossary.md).
- **Plain language.** Short sentences. Explain the "why," not just the "what."
- **Real, verified links only.** No placeholder or made-up URLs.
- **No em dashes.** Use commas, periods, semicolons, or parentheses.
- **Generic and universal.** Keep examples tool-agnostic where possible. This is an educational guide, not a product pitch.

## How to submit

1. Fork the repo and create a branch for your change.
2. Make the edit. Keep pull requests focused — one topic per PR is easier to review.
3. If you changed a step that has a screenshot, note whether the screenshot still matches.
4. Open a pull request describing what you changed and why.

Not comfortable with pull requests yet? That's fine, this guide is partly about learning that. Open an [issue](../../issues) in plain language describing what's wrong or missing, and it can be handled from there.
